# 「涟漪脚本」重构为「微软积分智能助手」设计文档

日期：2026-08-23
状态：待用户复核

## 一、主旨转变

当前「涟漪脚本」是一个**通用脚本自动化引擎**：用户可人工编排点击/滑动/输入/等待等步骤，配合市场、定时、内置脚本仓库使用。

重构后**彻底聚焦微软积分**：从"能做所有脚本"转为"只精通微软积分签到的专职助手"。用户点一下【一键签到】，自动完成 **登录 → 签到 → 搜索 → 阅读** 全链路，全程智能识别、零人工干预（真实二次验证除外）。

## 二、总体架构

不重写已验证的底层能力，只替换"通用编排层"为"专职智能体"。

### 2.1 保留并复用
- 无障碍服务 `AutoAccessibilityService`：手势分发（点击/长按/滑动/输入）、无障碍树读取、等待自愈
- 无障碍**三层保活**：分钟级心跳（ACTION_TIME_TICK）+ 守护协程 + AlarmManager 看门狗
- **智能识别层**：标题 3-gram 去重 `TextFingerprint`、多维广告识别（广告标记/CTA/类名/轮播页码）、误点检测与恢复 `isMisClickedAd/recoverToExpected`、坐标自适应 `CoordinateMapper`
- `AppLauncher`（ColorOS 分身启动）、`Permissions`（无障碍双恢复、悬浮窗、电池白名单判断）
- 悬浮运行状态（`FloatingControllerService` 改造成"运行中"指示条）

### 2.2 砍掉/下线（通用编排）
- 通用 `Script`/`Step` 模型、`ScriptParser`、`StepEngine`、手动 Step 编辑与相关 UI
- UI：脚本制作（`CreateScreen`/`StepEditSheet`/`StepCard`/`AppPickerSheet`）、脚本市场、计划调度、内置可编辑脚本仓库
- 底部导航由 4 Tab 精简为 **2 Tab：签到（主页）+ 设置**

### 2.3 新增
- `RewardsAgent`：专职状态机智能体，驱动全链路
- `RewardsStore`：参数（搜索次数/阅读篇数/亮屏时长）+ 账号配置 + 运行记录；凭据字段用 Android Keystore 加密存储
- 「一键签到」主页（进度/日志/结果）与设置页

## 三、核心智能体 `RewardsAgent`

一键触发后按状态机顺序执行，全程智能识别、失败自动降级重试，用户只看进度。

| 阶段 | 行为 | 智能识别 / 降级 |
|---|---|---|
| 0 准备 | 拉起 Bing、保持亮屏、待无障碍就绪 | 复用 `waitForRoot` 自愈等待 |
| 1 会话检测 | 读取首页判断登录态（头像/账号/"Sign in"） | 语义匹配节点，不依赖固定坐标 |
| 2 登录 | 自动填 Keystore 凭据 → 下一步 → 密码 → 提交 | 检测到邮箱验证码/短信/Authenticator 推送/滑块人机验证 → 暂停 + 高优通知，等用户处理后续跑 |
| 3 每日签到 | 定位「每日签到/Daily streak/阅读赚积分」入口领取 | 已领取则跳过（当日状态感知） |
| 4 搜索 ×N | 输入关键词 → 回车 → 等结果 → 回 Bing，循环 N 次 | 复用 1000 词词库去重+打乱；识别「真搜索成功」vs 拦截/无结果页，防无效刷分 |
| 5 阅读 ×M | 智能选非广告未读新闻 → 阅读 M 秒 → 返回，循环 M 篇 | 复用全部广告过滤/标题去重/误点恢复 |
| 6 收尾 | 汇总当日积分走向 → 通知 →（可选）熄屏 | 结果落盘到运行记录 |

设计约束：
- **全程日志**：每阶段写进度到悬浮条与历史记录
- **可配置参数**：搜索次数、阅读篇数、亮屏时长，默认合理值（如搜索 20、阅读 10），可在设置调整
- **剂量与风控**：每步之间随机化小延时；搜索达到 Bing 每日上限自动停止，不强行
- **运行方式**：仅手动一键触发（不设定时），运行时需手机亮屏

### 3.1 登录自动化边界（必须明确的现实约束）
- 账号/密码预存在 `RewardsStore`，Keystore 加密，脚本用无障碍 `ACTION_SET_TEXT` 自动填入
- 若触发**邮箱/短信验证码、Microsoft Authenticator 推送、滑块人机验证**等二次验证，脚本无法无人值守通过 → 状态机进入「等待人工」态，发高优通知，用户完成后点继续，链路自动续跑
- 这是"接近零人工且现实可落地"的边界，作为明确的产品约束写入

## 四、UI

### 4.1 签到主页
- 登录态卡片：是否在线、账号、今日概览
- 大【一键签到】按钮
- 实时进度步骤列表：绿=完成 / 转圈=进行 / 红=暂停待处理
- 最近一次运行汇总（签到 + 搜索 N 次 + 阅读 M 篇）

### 4.2 设置页
- 账号：微软账号 / 密码（Keystore 加密）
- 运行参数：搜索次数、阅读篇数、亮屏时长
- 无障碍服务状态 + 一键自愈
- 权限引导：WRITE_SECURE_SETTINGS / 悬浮窗 / 电池白名单 / 自启动

## 五、数据
- `RewardsStore` 本地 JSON：参数 + 账号配置 + 历史记录
- 凭据字段单独 Keystore 加密，明文不落盘

## 六、错误处理（零人工保障）
- 每阶段限次重试
- 障碍（网络/无结果/元素找不到）降级不崩溃
- 真验证码/Auth 推送/滑块 → 暂停 + 高优通知，用户处理后继续
- 无障碍被杀 → 复用三层保活自动恢复；恢复不了发引导通知

## 七、测试与部署
- 单元测试：标题去重、广告过滤逻辑、状态机迁移
- 真机 adb 全链路测试：目标设备 OPPO PLG110（ColorOS 16，adb 序列号 `3B15C200T6A00000`），安装 APK，逐阶段实测 Bing 登录→签到→搜索→阅读
- 注意：ColorOS 16 下 `pm grant ... WRITE_SECURE_SETTINGS` 需**手机重启后生效**，用于无障碍自动恢复

## 八、范围与不做
- 不做：通用脚本编辑/市场/定时，不做其它平台的积分
- 不保证：真实二次验证（邮箱/短信/滑块/Authenticator）无人值守通过——遇此暂停待人工
